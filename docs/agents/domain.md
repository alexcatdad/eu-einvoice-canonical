# Domain docs

## Layout

Single-context: GLOSSARY.md at the repository root and ADRs in docs/adr/.

## Before exploring

Read GLOSSARY.md and ADRs relevant to the area being explored.
If they do not exist, proceed silently. Domain-modeling creates them
lazily when terms or decisions are resolved.

## Vocabulary

Use the glossary's terms in proposals, issues, hypotheses and tests.
When a needed concept is missing, reconsider the terminology or note
the gap for domain-modeling.

## Decisions

Respect relevant ADRs. If a proposal contradicts one, identify the ADR
and explain why reopening the decision is justified.
