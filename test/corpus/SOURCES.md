# Public sample corpora

Real or official sample e-invoices that the weekly [corpus workflow](../../.github/workflows/corpus.yml) converts
at scale. The pins live in [`scripts/fetch-corpora.sh`](../../scripts/fetch-corpora.sh).

**None of these files is committed here.** They are cloned (sparse, shallow, at a pinned commit) into
`test/corpus/repos/`, which is git-ignored, in CI only, read by the converter and thrown away with the runner.
Nothing is redistributed, so copyleft licences (AGPL, EUPL, LGPL) do not reach this repository's licence (0BSD);
the report that is published contains counts, normalised error messages and repository-relative file paths, never file content.

Licences were read from each repository's licence file on GitHub on 2026-10-16. Where the licence covers the code and
not necessarily the sample files, the table says so.

## Expected errors

Some corpus files are broken on purpose or by accident; the real-world run reports them as `error`, and that is
the right answer. They are listed here so a reader of the report does not chase them.

| Files | Why they fail |
|---|---|
| phive-rules `simplerinvoicing/SI-UBL-1.0/*-error-*.xml`, `SI-UBL-1.1/*-error-*.xml`, `SI-UBL-1.2/*-error-*.xml` (Peppol BIS 2, 32 files) | Negative test files of the SimplerInvoicing validation rules: each removes the element its rule requires (BT-1, BT-5, a LegalMonetaryTotal amount, a TaxSubtotal amount, a line amount). Peppol BIS 2 makes those elements mandatory, so nothing is derived |
| ph-ebinterface / ebinterface-web `testinstance-*.xml`, `InvoiceExample1.xml`, `ebInterface_Instance_withExtension.xml` (ebInterface 3.0 and 4.0) | XMLSpy-generated schema instances whose InvoiceNumber is a single space |
| ebinterface-web `*-invalid.xml`, `*_invalid.xml` | Invalid by name: not well-formed, or without an invoice number or biller |
| zugferd-corpus `ZUGFeRDv1/fail/` and `Mustangproject/MustangGnuaccountingBeispielRE-20151008_504.pdf` | No invoice currency anywhere in the document |
| zugferd-corpus `Konik/acme_invoice-42_ZUGFeRD.pdf` | ZUGFeRD 1 BASIC without the mandatory TaxBasisTotalAmount and without any tax breakdown |
| zugferd-corpus `Intarsys/ZUGFeRD_1p0_EXTENDED_Kostenrechnung.pdf`, factur-x-py `zugferd-extended.xml` | A format 102 date `20139102` (month 91) |
| ph-ubl `ph-ublpe/.../test-ublpe20/` (Peru, UBL 2.0) | TaxSubtotal without a TaxableAmount: SUNAT 2.0 keeps the taxable bases in UBLExtensions, which are not mapped |

## Looked at and not used

| Source | Why |
|---|---|
| facturae.gob.es sample files | Published on the ministry's website, not in a repository with a licence; no verifiable reuse terms |
| Finvoice, e-arve (Estonia), eSLOG (Slovenia), ANAF e-Factura samples | The issuing bodies publish samples on their own sites without a licence statement. The only repositories found with such files were unlicensed or personal data dumps; phive-rules carries the official ones for the formats it validates and is already a corpus. `gobl-finvoice` adds Finvoice |
| ZATCA SDK (zatca.gov.sa) | Distributed as a download under ZATCA's terms, not a repository. `phive-rules` carries ZATCA's own samples, and `zatca-php` the SDK-style examples |
| OCA/l10n-italy, OCA/l10n-spain, OCA/l10n-poland (19.0) | FatturaPA/Facturae/Polish test files moved into Odoo itself; the OCA branches hold no invoice samples (checked at the pinned heads) |
| austriapro/ebinterface-standards | No licence file |
| capstone-se4gd/msm-integration and other repositories found by code search | Not invoice sample collections; no licence |

## Bumping a pin

Change the commit in `scripts/fetch-corpora.sh`. If the file belongs to the known-answer set
(`test/corpus/expected.json`), regenerate that with `scripts/corpus-manifest.ts`.
